# Подтверждённые динамические формы рода v068

Production-набор `exports/dynamic_gender_confirmed_variants_v066.csv` содержит 153 базовых ID: 13 реплик игрока, 10 реплик Оператора и 130 реплик NPC, грамматика которых обращена к выбираемому герою. Они включены в Lua-карту общего Message-hook; фактические runtime key и технические группы перечислены в `exports/dynamic_gender_runtime_manifest_v067.csv`.

Ещё 28 подтверждённых реплик игрока из Digimon Chat вынесены в `exports/dynamic_gender_chat_unhooked_variants_v066.csv`. Общий итог подтверждённых родовых строк — 181 базовый ID. Строки чата помечены `basis=player_self_chat_unhooked`: их нельзя включать в production-карту, пока не подтверждено, что Digimon Chat проходит через тот же Lua-resolver. Без отдельного перехвата они должны остаться нейтральными.

Колонки `male_protagonist_text` и `female_protagonist_text` всегда описывают выбранного героя. Для `role=player_address` они управляют формой обращения NPC, а для `role=operator` форма самого Оператора инвертирована:

- герой-мужчина → Оператор-женщина;
- герой-женщина → Оператор-мужчина.

Для строки `s910_169_640` меняется обращение Оператора к герою. Текст по-прежнему кладётся в инвертированную ветку Оператора: герой-мужчина выбирает `__F`, герой-женщина — `__H`.

Speaker ID копируется из базовой MBE-строки (`char_PLAYER_M` или `char_OPERATOR_M`) и не заменяется вручную. Во всех исходных message-таблицах используются именно эти базовые ID; движок сам переключает отображаемого героя/Оператора. Принудительные `char_PLAYER_F`/`char_OPERATOR_F` в вариантах могли бы обойти штатную логику и потому не применяются.

Суффиксы `_M` и `_F` из четвёртого столбца MBE не использованы как текстовые ID. Они являются voice/event aliases. Реализация создаёт новые строки `<base_id>__H` и `<base_id>__F`, а Lua-таблица выбирает их по `GetGender()`.

Двенадцать родовых реплик являются вариантами ответа внутри трёхстрочных `MessageTalkSel`-групп. Для них движок получает ID первой строки группы, а не ID конкретного ответа. Поэтому генератор создаёт две полные технические копии группы в исходном порядке и меняет только подтверждённую родовую строку. Остальные 141 runtime key являются прямыми сообщениями. Всего в MBE создаётся 354 технические M/F-строки.

Все строки сверены с текущими CSV и английским оригиналом Steam build 23514637. Текстовые управляющие теги (`{next}`) сохранены. В нескольких строках одновременно устранены очевидные механические формулировки: `Можете поспорить`, `ходил сюда`, `стал свидетелем аномального феномена`, `нечто Среднее`.

Нейтральные и естественно звучащие реплики в набор намеренно не включались: им не нужны две физические строки. Также исключены формы, относящиеся к собеседнику-дигимону или третьему лицу. Ручная классификация всех 583 кандидатов сохранена в `exports/dialogue_gender_style_review_v068.csv`.
