# Подтверждённые динамические формы рода v082

Production-набор `exports/dynamic_gender_confirmed_variants_v066.csv` содержит 141 базовый ID: 13 реплик игрока, 12 реплик Оператора и 116 реплик NPC, грамматика которых обращена к выбираемому герою. Финальная контекстная проверка исключила обращения к фиксированным дигимонам и боевым союзникам. Подтверждённые строки включены в Lua-карту общего Message-hook; фактические runtime key и технические группы перечислены в `exports/dynamic_gender_runtime_manifest_v067.csv`.

Исторический список `exports/dynamic_gender_chat_unhooked_variants_v066.csv` содержит 28 реплик игрока из Digimon Chat, который не проходит через общий Lua-resolver. В v071 все 28 строк переписаны в естественной родонейтральной форме; тем же проходом нейтрализованы ещё пять найденных ответов. Поэтому чат по-прежнему намеренно не включён в production-карту и не зависит от работы hook.

Колонки `male_protagonist_text` и `female_protagonist_text` всегда описывают выбранного героя. Для `role=player_address` они управляют формой обращения NPC, а для `role=operator` форма самого Оператора инвертирована:

- герой-мужчина → Оператор-женщина;
- герой-женщина → Оператор-мужчина.

Для строки `s910_169_640` меняется обращение Оператора к герою. Текст по-прежнему кладётся в инвертированную ветку Оператора: герой-мужчина выбирает `__F`, герой-женщина — `__H`.

Speaker ID копируется из базовой MBE-строки (`char_PLAYER_M` или `char_OPERATOR_M`) и не заменяется вручную. Во всех исходных message-таблицах используются именно эти базовые ID; движок сам переключает отображаемого героя/Оператора. Принудительные `char_PLAYER_F`/`char_OPERATOR_F` в вариантах могли бы обойти штатную логику и потому не применяются.

Суффиксы `_M` и `_F` из четвёртого столбца MBE не использованы как текстовые ID. Они являются voice/event aliases. Реализация создаёт новые строки `<base_id>__H` и `<base_id>__F`, а Lua-таблица выбирает их по `GetGender()`.

Двенадцать родовых реплик являются вариантами ответа внутри трёхстрочных `MessageTalkSel`-групп. Для них движок получает ID первой строки группы, а не ID конкретного ответа. Поэтому генератор создаёт две полные технические копии группы в исходном порядке и меняет только подтверждённую родовую строку. Остальные 129 runtime key являются прямыми сообщениями. Всего в MBE создаются 330 технических M/F-строк.

Все строки сверены с текущими CSV и английским оригиналом Steam build 23514637. Текстовые управляющие теги (`{next}`) сохранены. В нескольких строках одновременно устранены очевидные механические формулировки: `Можете поспорить`, `ходил сюда`, `стал свидетелем аномального феномена`, `нечто Среднее`. В v075 пара `s010_001_430__H/__F` синхронизирована с локализованной игрой слов `двадцатейший / Двадцатейшесть`, не меняя число runtime-ключей.

Нейтральные и естественно звучащие реплики в набор намеренно не включались: им не нужны две физические строки. Также исключены формы, относящиеся к собеседнику-дигимону или третьему лицу. Ручная классификация исходных 583 кандидатов сохранена в `exports/dialogue_gender_style_review_v068.csv`; дополнительные строки v069–v082 найдены отдельными source-checked проходами. Финальная проверка 595 базовых реплик Оператора оставила только два корректных множественных контекста (`толпа` и `герой + напарник`) и ни одного формального обращения Оператора к игроку.
