# Исправление ввода кириллического имени

## Причина

Проверено на `Digimon Story Time Stranger.exe` Steam build 23514637,
SHA-256 `ff9de825a543bf874cfb7e73ed951256d3ce4e8702957afa3b26ca6487a81688`.

Игра регистрирует ANSI-класс окна `GameMain` через `RegisterClassExA`. Поэтому
для русской системной кодовой страницы `WM_CHAR` передаёт однобайтовый CP1251:
например, `а` приходит как `E0`. В обработчике игры этот `wParam` ошибочно
считается готовым UTF-16 и сразу кодируется через
`WideCharToMultiByte(CP_UTF8)`. В результате `E0` становится U+00E0 `à`,
`E4` — `ä`, `EF` — `ï`, что точно соответствует пользовательскому скриншоту.

IME-ветка игры использует правильную последовательность
`MultiByteToWideChar(CP_ACP) -> WideCharToMultiByte(CP_UTF8)`. Ошибка находится
только в прямой обработке `WM_CHAR`.

Справка Microsoft:

- [RegisterClassExA](https://learn.microsoft.com/windows/win32/api/winuser/nf-winuser-registerclassexa)
- [WM_CHAR](https://learn.microsoft.com/windows/win32/inputdev/wm-char)

Аналогичные жалобы существуют для официально поддерживаемых японской и
корейской IME в PC-версии:
[Steam discussion](https://steamcommunity.com/app/1984270/discussions/0/573770913623204626/).

## Реализация

`native/name_input_fix/dinput8_proxy.c` собирается как x64-прокси
`installer/payload/dinput8.dll`. Игра импортирует из системного `dinput8.dll`
только `DirectInput8Create`; прокси загружает оригинал из `System32` и передаёт
ему вызов без изменений.

После `DirectInput8Create` окно игры уже существует. Прокси находит `GameMain`
текущего процесса и подменяет его WndProc. Только для `WM_CHAR` в диапазоне
`80..FF` байт преобразуется из текущей ANSI-кодировки в UTF-16. Все ASCII,
Backspace и остальные сообщения передаются без изменения.

EXE не модифицируется, поэтому исправление не зависит от RVA и ASLR.

## Безопасность установки

- сторонний `dinput8.dll` без маркера перевода не перезаписывается;
- установщик проверяет записанный SHA-256 перед обновлением собственного DLL;
- новый DLL и маркер входят в список добавленных файлов и удаляются при
  восстановлении бэкапа;
- исходный DLL, если он принадлежал предыдущей версии перевода, резервируется.

## Проверка

`native/name_input_fix/test.ps1` создаёт ANSI-окно `GameMain`, устанавливает
hook и проверяет преобразование CP1251 для `Юки`, `Алёна`, `Ёж`, а также
неизменность ASCII и Backspace. Дополнительно проверяются x64 PE-заголовок и
экспорты `DirectInput8Create`, `DstsRuInstallInputHook`,
`DstsRuInputFixVersion`.

Ограничение: hook исправляет новый ввод, но не мигрирует имя, уже сохранённое в
испорченном виде. Для проверки в игре нужно начать новое прохождение либо
дойти до нового окна переименования.

Преобразование подтверждено для русской системной ANSI-кодовой страницы
Windows (CP1251), которая воспроизводит исходную ошибку со скриншота. При иной
ACP или включённом экспериментальном режиме UTF-8 ANSI-окно игры может заменить
кириллицу до получения `WM_CHAR`; такие конфигурации этим hook не гарантируются.
